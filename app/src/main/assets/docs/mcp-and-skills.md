# MCP 服务器与扩展能力设置

进入“设置” -> “MCP 服务器”，管理 Model Context Protocol (MCP) 服务器配置，外挂本地或远程扩展能力（如查数据库、搜网页、浏览器控制等）。

MCP 配置分**两级作用域**：**全局**（所有项目共享，存 `~/.aicode/mcp.json`）与**项目级**（仅当前工作区生效，存 `<工作区>/.aicode/mcp.json`，可随项目 git 追踪）。生效配置 = 全局 + 项目合并，**项目级优先**，同名时项目项覆盖全局项。

## 1. 服务器列表页
*   以 iOS 分组列表展示当前项目生效的 server，每行左侧为方块图标，右侧状态 Pill 显示连接状态（已连接/连接中/连接失败/已禁用）。
*   每行两行布局：左侧第一行显示名称，第二行显示**来源 Pill（`全局` / `项目`）**、类型 Pill（`内置` 或 `HTTP`）与信息 Pill（已连接时显示「工具: N」，否则显示启动命令或 URL）；右侧显示状态 Pill 与右箭头。
*   **左滑行**露出「删除」按钮可移除该 server；点击行进入编辑。删除会作用于该行标注的作用域。
*   右上角「重新连接」按钮一键重连所有 server，「+」按钮添加新 server。
*   在容器内/外部直接编辑 `mcp.json`（全局或项目级）后，App 会在数秒内自动检测并刷新列表与连接状态：新增/启用的 server 自动连接，删除/禁用的自动断开，无需重启或手动重连。

## 2. 编辑器：基础设置 Tab
顶部**作用域**分段选择（`全局` / `项目`）：添加时默认「项目」，编辑已有条目保持其原作用域；下方「是否启用」开关控制该 server 是否参与连接。其余字段按传输类型切换（`远程 HTTP` / `本地 stdio`）：

### 远程 HTTP 类型
*   **名称**：别名标识（如 `fetch`、`github`）。
*   **服务器地址**：远程服务端的 Streamable HTTP 链接（如 `https://api.example.com/sse`）。
*   **自定义请求头**：键值对列表，可添加多条，用于填入认证 Token 等静态头部。

### 本地 stdio 类型
*   **名称**：别名标识。
*   **启动命令**：执行引擎或命令，例如 `npx`、`node`、`python`。
*   **命令参数**：参数列表，每项一个卡片（如 `-y`、`@modelcontextprotocol/server-xxx`）。
*   **环境变量**：键值对列表，传递给该进程的环境变量（如 `API_KEY`）。
*   **运行容器**：本地工作区模式跑在当前容器上；远程工作区模式下跑在「默认容器」上（设置 → 容器与镜像 → 默认容器，默认内置 Alpine）。切换容器后所有 stdio server 会自动断开并用新容器重新连接，HTTP server 不受影响。

## 3. 编辑器：工具 Tab
连接成功后可查看该 server 暴露的工具列表，每个工具一张卡片：
*   **工具开关**：右上角 Switch 可禁用单个工具（写入 `disabledTools`），禁用后该工具不再注入模型。
*   **描述与参数**：显示工具描述及其入参键名 pill。
*   **工具权限**：所有 MCP 工具统一走「工具权限」机制（与 Bash/writeFile 一致）：默认每次调用需审核，可在授权弹窗选择「始终允许」记住后自动放行。
*   未连接或未检测到工具时，点击右上角「刷新」按钮重新拉取工具列表。

## 4. 其他入口
*   编辑器右上角日志按钮可跳转到「日志」页并按该 server 名称过滤。
*   对于复杂的 MCP 配置，AI 也可在会话中通过 `manageMcp` 工具自动添加或管理，可用 `scope` 参数（`global`/`project`）指定作用域，默认全局。新增/移除后配置在**下一次会话生效**（新建会话时会自动重连未连接的 server）。

## 5. 技能（Skills）

进入“设置” -> “技能”，管理本机已安装的技能——一份份「按需加载的专项操作指令」，AI 在相关任务时主动加载使用。

### 列表页
*   按「当前项目 / 全局」两个**可折叠分组**列出技能（与「工具授权」页一致），分组标题可点击展开/收起。
*   每行一个技能：图标 + 名称 + 描述摘要，名称右侧以彩色勋章显示启用/禁用状态；点击行进入详情；**左滑露出「删除」按钮**删除该技能（会弹出确认框，删除即移除技能目录，不可恢复）。
*   技能来源分两级：**全局**技能存放在 `~/.aicode/skills/`（跨项目共享，容器内实际路径，跨升级保留）；**项目级**技能存放在 `<工作区>/.aicode/skills/`（仅当前工作区生效，可随项目 git 追踪）。同名技能项目级优先。
*   技能目录内包含 `SKILL.md`（或兼容的 `CLAUDE.md`）即自动识别。**App 常驻监听技能目录与配置文件**（约 2 秒轮询）：在容器内/外部手工添加、删除、改名技能目录或编辑 `skills.json` 后，列表会在数秒内自动刷新，无需重进页面。

### 详情页
*   三张分组卡片，左上小标题与设置主页分组一致：**「是否启用」**（名称、来源与启停开关）、**「摘要」**（描述）、**「正文」**（`SKILL.md` 指令正文，等宽字体，可选中复制）。

### 启停
*   详情页「是否启用」开关控制该技能是否参与 AI 会话：关闭（禁用）后，该技能不再出现在系统提示的「可用技能」清单中，`loadSkill` 也无法加载，可减少上下文占用。
*   禁用名单写入 `skills.json`：全局为 `~/.aicode/skills.json`，项目级为 `<工作区>/.aicode/skills.json`，格式 `{"disabled": ["技能名"]}`；两级取并集，任一作用域禁用即生效。也可直接手工编辑该文件，数秒内自动生效。
