# 容器与镜像 (Container)

进入「设置」->「容器与镜像」，管理 AI 命令执行的后端。列表单选切换当前生效的 profile，后端分两类：**本地容器镜像**（PRoot）与**远程 SSH**。两者必居其一，选中即按该后端执行命令、读写文件、运行终端。

所有容器统一管理：均可**编辑**、**重置**、**左滑删除**，列表名称后带来源标记（内置 Alpine=「内置」、导入的本地镜像=「自定义」、远程 SSH=「SSH」，颜色区分）。App 内置一个 Alpine 容器，首次启动自动添加到列表（带「内置」标记），之后与自定义镜像完全一样——可编辑、可重置、可删除；删光后列表显示空态，可一键恢复内置 Alpine。

> **列表左侧图标**：容器被选中并运行后，App 会在容器内读取系统标识自动识别系统类型，并在列表中显示对应系统图标（目前支持 Alpine、Ubuntu、Debian、CentOS），识别不到时显示默认图标。识别结果缓存在 App 缓存目录；重置、重装或更换镜像后缓存自动失效，下次运行重新识别。

## 1. 本地容器镜像

通过 PRoot 在手机本地运行一个 Linux rootfs，AI 的命令、文件、终端都在这个容器内执行。适合无需远程服务器、离线或要直接操作手机本地文件的场景。

### 内置 Alpine 镜像
App 自带 Alpine 镜像（来自内置资源），首次启动默认添加并选中，shell 路径自动选择（bash/sh），无需配置。首次进入终端时弹出**交互式初始化菜单**（见下方「初始化脚本」），由用户选择安装基础工具（python3、git、pip、nodejs、npm、bash、curl、ripgrep 等）。内置 Alpine 同样支持：

*   **编辑**：可改名称、挂载、proot 参数、环境变量；镜像来源固定为内置，不支持导入覆盖。
*   **重置**：恢复出厂——清掉用户修改的配置、删除 rootfs 目录（含已安装的工具与配置），下次使用时重新解压并初始化。
*   **删除**：左滑删除；删除后若列表为空，空态页提供「恢复内置 Alpine」按钮一键加回。

> **首次使用需先在终端页面完成初始化**：容器首次使用（解压 rootfs、安装基础工具）只在进入**终端页面**时自动触发。在此之前，Git 页、AI 的 Bash 工具、依赖本地容器的 MCP 命令会直接提示「请先进入终端页面完成初始化」，而不会自动初始化，避免多入口并发初始化互相打断。

### 自定义镜像
点击右上角「+」号选择「本地镜像」类型，新建自定义 profile：
*   **名称**：镜像配置别名。
*   **shell 路径**：如 `/bin/sh`、`/bin/bash`。
*   **挂载**：逐项添加/删除，每项分「本地目录」「容器目录」两个输入框（如本地 `/sdcard` → 容器 `/mnt/sdcard`），把宿主目录挂进容器（每项对应一个 `-b 本地:容器` 参数）。
*   **proot 参数**：逐项添加/删除的参数列表，每项原样追加到 proot 启动参数。
*   **环境变量**：逐项添加/删除的键值对，注入容器内进程（覆盖同名默认值）。
*   **镜像文件**：选择 tar.gz / tgz / tar.xz / txz 格式的 rootfs 镜像文件，选择后显示文件名。保存时会把镜像包复制一份到 App 私有目录（`filesDir/rootfs_images/`），之后重置/重装容器都从私有副本重新解压，不依赖原始文件；删除镜像时私有副本一并清理。

自定义镜像只保证能起 shell 执行命令，不接管镜像源。首次进入终端时显示**交互式初始化菜单**（见下方「初始化脚本」），与内置 Alpine 完全一致——由用户选择自动安装依赖、自定义安装（逐个询问并单选运行时主版本）、手动安装不再提示、或退出；自动/自定义安装都会先列出安装清单，输入 `y` 确认后才开始安装；换源时可从多镜像候选里选择（含自动探测），装包失败不阻塞进入 shell。重置容器会删除其 rootfs 目录，下次使用时重新解压并重新进入初始化菜单。

### 初始化脚本（provision）

容器初始化由 `provision.sh` 完成，所有容器（内置 Alpine / 自定义镜像）统一走交互菜单：

*   **脚本位置**：`~/.aicode/provision.sh`（App 私有目录 `filesDir/aicode/provision.sh`，经绑定即容器内 `/root/.aicode/provision.sh`，随 App 内置、启动时自动提取，跨容器重装保留）。
*   **宿主组 ID 修复**：每次进入终端（含已配置的存量容器）会先把宿主透传的补充组（Android AID：3003 inet、9997 everybody、App 自身 uid 派生 gid 等）幂等补进 `/etc/group`（`gid_` 前缀命名，先清再补防残留），避免 `groups` 等命令因查不到组名报警；静默执行，不阻塞进入 shell。
*   **交互菜单（所有容器一致）**：rootfs 解压完成后进入终端，自动弹出菜单：
    1. **自动安装依赖（推荐）**——先列出安装清单（基础工具 bash/curl/ripgrep/git + Node.js + Python 3），输入 `y` 确认后进入镜像源选择，随后按包管理器（`apk`/`apt-get`/`dnf`/`yum`/`pacman`）安装基础工具与 Node.js、Python（含 pip、npm）。安装成功写入完成标记；失败可重新进入终端重试，不阻塞进入 shell。
    2. **自定义安装**——逐个询问是否安装 Node.js / Python 3 / Java / Go / Rust / PHP（Node、Python 默认装，其余默认跳过），答 `y` 后显示该运行时在仓库中可用的**主版本包**（纯包名单选，如 Debian 下 Java 的 `openjdk-21-jdk-headless`/`openjdk-25-jdk-headless`、Alpine 下 `openjdk17-jdk`/`openjdk21-jdk`、PHP 的 `php8.4-cli`/`php83`，回车默认第 1 个）；基础工具始终安装。选择完成后更新软件包索引、列出安装清单，输入 `y` 确认后进入镜像源选择再开始安装。安装成功写入完成标记；失败可重新进入终端重试，不阻塞进入 shell。
    3. **手动安装（不再提示）**——写入跳过标记，之后进入终端不再弹菜单，由用户自行在容器内装工具。想恢复菜单请重置容器。
    4. **退出**——本次不安装，下次进入终端仍会提示。
*   **镜像源选择**：内置多镜像候选（华为云、清华 tuna、中科大 ustc、腾讯云、阿里云），换源时 `1) 自动探测（推荐）`——按当前包管理器实测各镜像真实内容路径的可达性（apk 要求 http 直连可用、apt 接受重定向、dnf/pacman 有响应即可），自动跳过失效/被墙的镜像（如阿里云曾全站 403）；也可 `2~6)` 指定镜像或 `0)` 不换源保持默认。换源会备份原配置，失败自动恢复，不阻塞安装。**内置 Alpine rootfs 不再预置国内源**（保持官方 dl-cdn），镜像源统一由本菜单在初始化时按需切换。
*   **包清单与主版本在脚本内**：基础工具、自定义安装的运行时（Node.js/Python/Java/Go/Rust/PHP）及其在各包管理器下的包名映射、主版本候选（Java 的 openjdk 系列、PHP 的 php8x 系列等）都维护在 `assets/aicode/provision.sh` 内，改依赖只需编辑该脚本并同步升 `LinuxContainerEngine.PROVISION_VERSION`（触发存量容器重跑，已装包幂等跳过），无需改 App 代码。

> 注意：所有容器的 rootfs 都只解压不自动装包，装包与否由用户在初始化菜单里决定；重置或重装容器后初始化流程会重新执行。

## 2. 远程 SSH（远程工作区模式）

选中远程 SSH 镜像后即进入**远程工作区模式**：AI 的一切操作都在远程服务器上进行——**读写文件、执行命令、跑终端全部在远端**，`~/workspace` 映射为远程服务器上的「远程工作区路径」，本地手机仅作为操作界面，本地容器与本地文件不参与执行。适合远程服务器上已有完整工具链、或想让 AI 直接操作远程项目的场景。

底层通道：
*   **命令执行**：SSH exec channel（AI 的 Bash 工具）。
*   **文件读写**：SSH exec channel（文本用 `cat`/重定向读写，二进制用 `base64` 中转；不使用 SFTP——sshj 的 SFTP 实现有崩溃 bug）。
*   **终端交互**：SSH shell channel。

### 默认容器
远程模式下仍需要本地跑的服务（如 MCP stdio server）运行在**默认容器**上——默认内置 Alpine，可在列表下方的「默认容器」分组改为任意本地容器。切换容器（含切到远程 SSH）后，所有 stdio MCP server 会自动断开并用新容器重新连接；HTTP MCP 不依赖容器、不受影响。

### 前置：配置 SFTP 通道
远程 SSH 复用「连接与同步」页（详见 `remote-servers.md`）里配置的 **SFTP** 通道的连接信息（主机、端口、用户名、密码）。因此先在那里建好一个 SFTP 连接通道；FTP 与本地通道不支持 SSH exec，不会出现在可选列表中。

### 新建远程 SSH 镜像
点击右上角「+」号选择「远程 SSH」类型：
*   **名称**：镜像配置别名。
*   **SSH 连接通道**：下拉选择一个已配置的 SFTP 通道。若无可用通道，下拉菜单与输入框下方会提示先去「连接与同步」页配置，此时保存按钮不可用。
*   **远程工作区路径**：远程服务器上的目录，AI 的 `~/workspace` 将映射到此路径。选中通道时会自动填一个默认值（如 `/home/<用户名>/workspace`），可手动修改。

### 连接行为
*   **自动连接**：App 启动时若当前是远程 SSH 模式，会在后台自动连接；连接失败不阻塞 UI，首次命令时会再触发重试。
*   **保活与自动重连**：连接建立后启用 SSH 心跳（每 30 秒）防止空闲断连；连接断开时由监督协程自动重连（指数退避 5 秒起、最长 30 秒），App 回到前台也会立即触发一次重连。重连成功后会重新加载工作区、并重新同步内置文档到远程。
*   **连接状态指示**：远程模式下对话顶部栏会显示 `SSH：已连接 / 连接中 / 连接失败 / 未连接` 状态，未连接时消息区显示等待提示，避免空白。
*   **工作区路径自举**：远程工作区路径若在服务器上不存在，连接成功后会自动 `mkdir -p` 创建；若该目录下没有任何文件夹，会自动创建一个名为 `default` 的默认工作区，保证 AI 始终有可用的 `~/workspace`。

### 本地保留项（不随远程模式迁移）

远程模式下 AI 的**命令执行、文件读写、终端、工作区**都在远端服务器上，但以下配置与数据仍保存在**手机本地**（`~/.aicode/`，即宿主私有目录）：

*   **记忆（memory）**：全局与项目级记忆都存本地。项目级按 `<项目名>-<标识哈希>` 分目录隔离，标识哈希由 **IP+端口+路径** 计算，不同服务器/路径的同名工作区（如都叫 `default`）不会混淆；远程服务器上不会出现这些记忆文件。
*   **技能（skills）**：技能清单与 `SKILL.md` 正文从本地加载，AI 可正常 `loadSkill`。但技能正文里引用的脚本路径（如 `/root/.aicode/skills/<name>/x.py`）在远程服务器上不存在，远程模式下执行这类技能脚本会失败——技能主要面向本地模式。
*   **MCP 服务器**：HTTP MCP 由 App 直接连接（不依赖任何容器）；stdio MCP 运行在「默认容器」（本地 PRoot 容器）上，不在远程服务器。`mcp.json` 配置也在本地。
*   **权限规则**（`permissions.json`）：工具授权由 App 本地判定，远程模式同样生效。
*   **工具输出日志**（`tool-output`）与 FileLogger 日志：本地。
*   **聊天历史 / 模型与提供商配置 / API Key / 应用设置**：本地。
*   **git 署名与凭证**：git 页面保存的**署名**（user.name/email）通过 `git config` 写入当前执行环境——远程模式下即写入**服务器**的 git 配置（服务器 `~/.gitconfig` 或工作区 `.git/config`），本地模式写入容器。**凭证**以 `git-credentials` 文件为唯一真源（手机本地 `~/.aicode/git-credentials`，每主机一条），注入范围限定**工作区根目录**下的仓库：本地容器经 `includeIf gitdir:/root/workspace/` 加载 store helper；远程服务器可在凭据页开启「自动注入凭证」开关（按服务器独立记忆，首次进入会询问），把凭据同步到服务器 `~/.aicode/` 并经 `GIT_CONFIG_GLOBAL` 注入。两者都不影响工作区之外/服务器其它目录的 git 仓库，也不改动服务器用户的全局 git 配置。

> 注意：远程模式下 AI 视角的 `~/.aicode` 指向远程服务器上的 `~/.aicode`（目前仅自动同步了内置 docs 文档），上述本地项不会出现在远程服务器上。
*   **文档同步**：连接成功后会把内置的 `~/.aicode/docs/` 文档同步到远程服务器同名目录，使远程模式下 AI 也能查阅这些设置说明文档。

### 认证方式
当前远程 SSH 执行后端复用 SFTP 通道的**密码**认证。私钥认证在底层已支持，但 UI 暂未提供选择入口。

## 3. 编辑、重置与删除

所有容器（含内置 Alpine）统一管理：

*   **编辑**：行尾铅笔图标。本地镜像可改名称、Shell、挂载、proot 参数、环境变量、镜像文件；远程 SSH 可改名称、通道、远程工作区路径。编辑内置 Alpine 时镜像来源固定为内置，不支持导入覆盖。
*   **重置**：编辑弹窗右上角刷新图标（远程 SSH 无本地数据，不提供）。内置 Alpine 恢复出厂（清配置 + 删 rootfs）；自定义本地镜像删除 rootfs 目录，下次使用时重新解压。均为破坏性操作，点击后需确认。
*   **删除**：行上左滑露出红色删除按钮。删除本地镜像会一并清理其 rootfs 目录；删除远程 SSH 镜像只删配置，不影响远程服务器上的数据。内置 Alpine 也可删除，删光后空态可一键恢复。

> 提示：删除全部容器后（含内置 Alpine），AI 命令执行会回退到内置 Alpine 兜底，App 不会因此不可用；重新打开「容器与镜像」页可在空态恢复内置 Alpine 或添加新镜像。
